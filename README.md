# Лабораторна L10: суддя всередині периметра

Цей файл пояснює, що де лежить і як запускати. Порядок дій і пояснення в темі; тут лише практика. Лабораторна працює на репозиторії лабораторної L09 (`paypilot-l09-eval`): нових наборів немає, змінюється тільки модель судді.

## Нагадування, коротко

Корінь курсу завжди `~/paypilot`: стенд у `~/paypilot/paypilot-stand`, цей
репозиторій — у `~/paypilot/l10` або `~/paypilot/paypilot-l10-eval`

1. Підняти локальний стенд: у 
`~/paypilot/paypilot-stand` — `docker compose up -d --build`,
потім 
`docker exec -it paypilot-stand-stand-1 python scripts/doctor.py`.
2. Склонувати допоміжний репозиторій поруч зі стендом:
   `git clone https://github.com/alex-pancho/paypilot-l10-eval ~/paypilot/l10`
   Перейти у папку репозиторію:
   `cd ~/paypilot/l10`

## Що потрібно мати

- Ваш `sets/l09_labels.jsonl` із 12 кейсами, розмічений на L09 (мітки закомічено).
- Звіт хмарного калібрування на цих 12 кейсах: `reports/calibration-l09_labels-<мітка часу>.json`. Якщо його немає, зніміть зараз: `docker compose run --rm --entrypoint python eval tools/calibrate_run.py l09_labels` з хмарним `JUDGE_MODEL` (за замовчуванням `claude-haiku-5-5`, потрібен `ANTHROPIC_API_KEY`). Не міняйте набір і рубрику.
- Ollama на хості з моделлю, яка проходить контракт з теми (файл ≤ 6 GB, підтримує `format`). Розмір видно в `ollama list`.

## Що в патчі

| Файл | Що змінилося | Куди покласти |
| --- | --- | --- |
| `judge.py` | змінна `JUDGE_FORMAT`: `json` (як було), `schema` (схема виходу), `none` (без `format`) | замінити ваш `judge.py` у корені репозиторію |
| `tools/calibrate_run.py` | відповідь без валідного JSON рахується як `ERROR` і не обриває прогін; у виводі й звіті є час прогону, середній виклик, кількість `ERROR` і частка викликів, де цитату знайдено у відповіді | замінити |
| `tools/compare_judges.py` | додатково друкує час прогону | замінити |

Вивід L09 (рядки кейсів, самоузгодженість, узгодженість, групи) не змінився: нові рядки додано в кінці.

## Налаштування

У `.env`:

```
JUDGE_MODEL=ollama:<тег моделі>
OLLAMA_URL=http://host.docker.internal:11434
```

З контейнера `localhost` це сам контейнер, тому Ollama на хості вказується через `host.docker.internal`. Температура судді за замовчуванням 0.

Змінні `JUDGE_FORMAT` і `RUNS` передавайте через `-e`, як у командах нижче, інакше контейнер їх не побачить.

**Детальні налаштування [ollama](README-ollama-judge.md)**


## Кроки

**Крок 1. Зв'язок із моделлю.** Самотест судді:

```
docker compose run --rm --entrypoint python eval judge.py
```

Має вивестися JSON із `verdict` і `judge_model` (ваш тег). Якщо ні, див. розділ «Якщо щось пішло не так».

**Крок 2. Контракт на одному кейсі.**
1. Скопіюйте рядок `LB-11` зі свого `sets/l09_labels.jsonl` у новий файл `sets/l10_one.jsonl` (мітка вже в ньому).
2. Із схемою:
   ```
   RUNS=3 JUDGE_FORMAT=schema docker compose run --rm -e RUNS -e JUDGE_FORMAT --entrypoint python eval tools/calibrate_run.py l10_one
   ```
3. Без `format` (лише прохання в промпті):
   ```
   RUNS=3 JUDGE_FORMAT=none docker compose run --rm -e RUNS -e JUDGE_FORMAT --entrypoint python eval tools/calibrate_run.py l10_one
   ```
4. У кожному запуску запишіть: скільки відповідей розпарсилося (літера `E` у вердиктах і рядок «без валідного JSON»), чи вердикти однакові, у скількох викликах цитату знайдено у відповіді. Разом шість відповідей.

Не використовуйте для цього `runner.py`: він судить свіжу відповідь агента, а не записану.

**Крок 3. Калібрування на 12 кейсах.**

```
JUDGE_FORMAT=schema docker compose run --rm -e JUDGE_FORMAT --entrypoint python eval tools/calibrate_run.py l09_labels
```

Це 60 викликів. Запишіть самоузгодженість, узгодженість з інтервалом, групи, час прогону й середній виклик. Режиму двох викликів у `judge.py` немає: для режиму двох викликів час порахуйте множенням на 2.

**Крок 4. Дві таблиці поруч.**

```
python3 tools/compare_judges.py reports/calibration-<хмара>.json reports/calibration-<локальний>.json
```

Скрипт друкує узгодженість, інтервали, час і кейси з різним вердиктом. Який файл хмарний, а який локальний, видно за полем `judge_model` у звіті. Висновок за правилом: судді різняться, лише якщо інтервали не перекриваються. На 12 кейсах різниці майже напевно не видно, тож рішення за розкладом промахів: чи мають вони спільну ознаку.

**Крок 5. Рядок вартості.** t_local = час прогону / кількість викликів (скрипт друкує середній виклик). Гроші 0, секунди = t_local × виклики релізного прогону × режим.

**Крок 6. Чернетка рекомендації.** Перші чотири розділи `model-selection-recommendation.md` за шаблоном з теми.

Перед кроком 1 запишіть прогноз із трьох чисел (див. тему). Після кроку 5 порівняйте.

## Що знаходиться у звіті

`reports/calibration-<набір>-<мітка часу>.json` містить `judge_model`, `temperature`, `runs`, `self_consistency`, `agreement`, `agreement_wilson`, а з патчем ще `elapsed`, `t_call_mean`, `errors`, `quote_found`. Порівнюйте звіти тільки з одного набору й однієї версії рубрики.

## Якщо щось пішло не так

| Що бачите | Причина і що робити |
| --- | --- |
| Помилка з'єднання, довге очікування без виводу | Контейнер не бачить Ollama. Перевірте `OLLAMA_URL` (не `localhost`), що Ollama запущено й модель є в `ollama list` |
| `judge returned no JSON` або `non-binary verdict` на самотесті | Модель не тримає форму. Поставте `JUDGE_FORMAT=schema`; якщо тег не підтримує `format`, це не кандидат за контрактом |
| У вердиктах багато `E` (ERROR) | Те саме, але на прогоні: запишіть частку, це результат контракту, а не помилка скрипта |
| Усі кейси мають один вердикт | Модель заповнює схему, не читаючи відповіді. Перевірте цитати: чи вони з відповіді (рядок «цитата знайдена») |
| Час прогону в десятки разів більший за очікуваний | Модель вантажиться заново на кожен виклик або бракує RAM. Запишіть у рекомендації як рядок про залізо, набір не міняйте |
| Кейси мають статус `SKIP` | `JUDGE_MODEL` не задано або `not-used` |

## Чого не робити

- Не міняйте набір, мітки, `criterion`, `answer_under_test` і `rubric_version` між двома прогонами. Інакше порівнюється не модель, а набір.
- Не дорозмічуйте кейси, на яких локальний суддя «точно впорається».
- Не пишіть «локальний суддя безкоштовний»: гроші нуль, секунди ні.
- Не комітьте `.env` і ключі.
